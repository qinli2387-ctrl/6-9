# 四科摸底与初始训练权重任务报告（2026-08-17）

## 1. 任务目标

在上一轮 FSRS 词汇闭环之后，继续实现短版听、读、写、说摸底，并把结果保存为用户的初始训练权重，保持正式应用云端优先、用户数据按账号隔离。

## 2. 修改前基线

- 项目已有目标设置、24 周地图、前 4 周关卡和 FSRS 词汇复习。
- 路线图仍缺四科摸底；每日任务是固定的听力、词汇、写作组合。
- 正式 Sites 项目仍返回 `Sites project not found`，D1 生产写入和跨设备同步无法验收。
- 本地源码通过 GitHub `main` 分支 ZIP 归档恢复；Git fetch 在本机多次因连接重置失败，`origin` 已保留但未强制覆盖远端。

## 3. 已实施修改

- 新增 `skill_baselines` 表和 `drizzle/0004_gifted_stranger.sql`，保存综合起点、四科分数、估计 band、训练权重和更新时间。
- 新增 `lib/placement-content.ts`、`lib/placement.ts` 与 `lib/placement-utils.ts`：原创听力/阅读/写作/口语内容、客观题评分、写作透明启发式评分、口语计时自评、权重归一化和加权每日任务。
- 新增正式 `/placement`、演示 `/demo/placement`、正式 API `/api/placement/complete` 和无数据库演示 API `/api/demo/placement`。
- 新用户目标设置后进入四科摸底；仪表盘显示初步起点与四科权重，并在生成当天任务时优先安排权重最高的两项技能。
- 新增原创 `public/audio/placement-listening.wav` 与 `placement-listening.vtt`，音频不上传；写作和口语结果明确标注为初步估计，不冒充官方成绩。
- 补充响应式样式、键盘可操作单选项、字幕轨道、减少动画兼容和手机布局。

## 5. 代码审查与安全检查

- 正式 API 只接受认证 `userId`，基线查询和 upsert 均以该用户主键为边界；演示 API 不写入任何用户数据。
- 客户端提交的分数、band、权重均不被信任；服务端从答案、文本、计时和自评重新计算。
- 写作文本限制在 2000 字符以内；计时、研究事件和音频均不上传第三方；没有新增密钥、密码、Token 或 `.env`。
- P2 注意：短测只适合作为训练分配信号，不可当作官方 IELTS 成绩；已有界面文案和结果页均明确说明。
