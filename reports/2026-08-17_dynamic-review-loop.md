# 动态错题复习闭环实施报告

日期：2026-08-17

## 基线

- 第 3 周标记为复习关，但使用固定的五道题。
- 关卡 API 只保存总分、星星和 XP，不保存逐题错误。
- 词汇 FSRS 队列独立存在，关卡无法消费到期词卡。
- Drizzle 有五个迁移，但没有仓库级 Wrangler 本地 D1 配置或空库验证命令。

## 变化

- 新增 `learning_errors` 表和迁移 `0005_demonic_harpoon.sql`，保存来源、技能、错因、题目快照、错误次数、到期和解决状态。
- 建立听力五类、阅读五类错因 taxonomy。
- 四科摸底与普通关会在服务端记录答错的听力/阅读题；重复答错使用用户、来源类型和题目 ID 做幂等更新。
- 第 3 周正式关卡动态选择最多五项：优先三道到期错题，再补 FSRS 到期词汇；不足时由另一类补齐。
- 提交动态复习时，服务端重新校验每个 ID 的用户归属、状态和到期时间。答对错题会标记解决；词汇答对映射 FSRS `Good`，答错映射 `Again`。
- 当错题和词卡队列都为空时，回退到原来的基础复习关，避免学习路线被锁死。
- Dashboard 展示当前账号的到期错题和词汇数量，并在第 3 周解锁后进入个性化复习。
- 抽出共用的词汇调度写入函数，普通词卡页和动态复习关写入相同 FSRS 状态与日志。
- 新增 `wrangler.local.jsonc`、本地迁移脚本、D1 验证脚本、SQLite 空库验证脚本和 `docs/LOCAL_DEVELOPMENT.md`。

## 失败与处理

- 首次完整测试在 Vinext 构建尚未结束时提前运行，因 `dist/server/index.js` 尚未生成导致两个渲染测试失败。等待构建进程退出并补充失败路径后重跑，11/11 通过。
- `pnpm db:verify:local` 首次因缺少 Windows VC runtime DLL 返回 `write EOF`；安装微软官方 VC++ x64 运行库后，`workerd` 启动并通过真实 D1 验证。安装包 SHA-256 为 `843068991DAAA1F73AD9F6239BCE4D0F6A07A51F18C37EA2A867E9BECA71295C`。
- 正式 Sites 项目仍不可访问，本轮没有执行远端迁移或账号同步测试。

## 独立审查发现与修复

- P1：空复习队列会让第 3 周页面抛错，阻断后续关卡。已增加基础复习回退，同时防止客户端在有到期内容时主动绕过个性化队列。
- P2：数据层原本依赖 API 做答案范围校验。已在错题写入函数再次验证选项索引和技能/错因匹配。
- P2：动态题目 ID 可能被替换为其他账号的数据。所有读取和更新都同时使用记录 ID 与认证 `userId`，且提交时重新验证到期状态。
- P2：词汇调度逻辑若在两个 API 中复制会漂移。已抽出 `scheduleVocabularyCard` 共用实现。
- P1：D1 首次播种 12 张词卡超过单条绑定参数上限，导致第 3 周页面 500。已改为每批 6 张、按唯一索引幂等写入，并由集成测试覆盖。
- P2：Vite 开发服务器会尝试监听被浏览器锁定的验证目录。已忽略 `work/**` 和 `.wrangler/**`。

## 安全与数据一致性

- 所有 `learning_errors`、`vocab_cards`、`level_progress` 和 profile 查询均按认证 `userId` 过滤。
- 客户端只提交答案索引和复习来源 ID；正确答案、归属、到期和评分均由服务端重建。
- 错题快照只含学习题目、选项和解释，不含写作正文、口语内容或账号凭据。
- 远端迁移、项目替换、数据导出和生产发布均未执行。
